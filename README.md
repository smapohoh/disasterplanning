## 실행

### 계정·그룹 기능 로컬 실행

Node.js 24 이상에서 두 터미널을 사용합니다.

1. `npm run server` → 로컬 계정 서버 `127.0.0.1:3011`
2. `npm run dev` → `http://127.0.0.1:3000`

오프라인 검증은 빌드 후 `npm run preview -- --port 3010 --strictPort`에서 합니다. Vite가 `/api`를 로컬 계정 서버로 연결합니다. 서버는 localhost에서만 열리므로 친구의 다른 기기에서는 아직 접속할 수 없습니다. 외부 배포·유료 서비스 연결은 하지 않았습니다. 기존 Vercel 정적 사이트에는 계정 서버가 없으므로 이 변경을 그대로 올려도 계정 기능은 동작하지 않습니다.

회원가입/로그인 → 그룹 없는 홈 → 그룹 생성 → 대표 자동 지정 → ‘멤버 초대’ → 7일 만료 링크 복사/공유 → 초대받은 사람의 가입/로그인 → 참여 확인 흐름을 제공합니다. 다중 그룹을 지원하고 그룹 정원은 6명입니다. 중복 참여는 인원을 늘리지 않습니다.

계정·그룹은 `.local/moida.sqlite`에 저장하며 Git에서 제외했습니다. 비밀번호는 scrypt와 개별 salt로 해시하고 세션은 HttpOnly/SameSite 쿠키로 관리합니다. 서버도 대표·멤버 권한을 검증하며 동시 변경은 충돌을 알립니다. 이메일 인증·메일 발송·비밀번호 재설정은 아직 지원하지 않습니다. 테스트용 정보로 사용하세요.

기존 `moida-plan-v2` 체험 데이터는 브라우저에 그대로 보존하며 계정 그룹으로 자동 가져오지는 않습니다. 그룹별 계획은 별도로 기기에 저장합니다. 연결이 없으면 ‘저장한 그룹 오프라인 열기’로 마지막 그룹을 볼 수 있습니다. 오프라인 변경은 기기 내 저장이며 서버로 자동 병합되지 않습니다.

`npm test`는 임시 데이터베이스에서 가입·로그인·초대·중복 참여·권한·대표 이양·로그아웃·동시 변경 충돌을 검증하고 테스트 파일을 정리합니다.

## 핵심 흐름

1. 지금 할 일: 역할별 행동과 예시 만남 장소를 바로 확인
2. 약속대로 움직여 보기 → 도착 표시 → 다음 행동과 가족별 계획 확인
3. 우리 약속: 첫/대체 만남 장소, 연락 두절 약속, 구성원별 상황 수정
4. 함께 확인: 각 역할로 직접 답하기 → 이해 확인 진행률 표시
5. 약속 수정 시 이전 이해 확인 전체 초기화

입력/확인/연습 기록은 이 브라우저 localStorage에 저장됩니다. 실제 초대, 메시지 전송, 위치 추적, 공식 재난 알림, 다중 사용자 동기화, 검증된 대피소 정보는 제공하지 않는 UI 프로토타입입니다.

## 대시보드 · 재난 상태 · 오프라인 지도

홈에서 구성원별 행동 계획과 입력률을 봅니다. ‘재난 상황 확인’을 켜면 안전/도움 필요/미확인 상태와 현재 계획 확인 여부를 별도로 기록합니다. 실제 다른 기기와 동기화되지는 않습니다.

지도는 서울숲 주변 약 600m의 실제 OSM 벡터 데이터를 예시로 제공합니다. 기존 계획의 장소가 다르면 불일치를 표시합니다. 다른 주소를 자동으로 검색하거나 위치를 추적하지 않습니다.

온라인에서 ‘지도 · 오프라인 저장’ → ‘이 지역 오프라인 저장’을 누르세요. 앱과 지도 저장 후 같은 브라우저·같은 주소에서 네트워크 없이 다시 열 수 있습니다. 브라우저 저장 공간 삭제/자동 정리 시 자료가 사라질 수 있습니다.

프로덕션 빌드의 `scripts/create-sw.mjs`가 내용 해시 기반 서비스 워커를 생성합니다. Vite 개발 모드는 오프라인 저장을 제공하지 않으므로 `npm run build` → `npm run preview`로 검증하세요.

## 로컬 수정: 계획과 리마인드

현재 로컬 작업은 ‘계획 작성 → 서로 리마인드 남기기 → 받는 사람 역할로 약속 재확인 → 요청자 화면에서 확인 결과 보기’를 핵심 경험으로 합니다. 리마인드는 수동·기기 내 기록이며 실제 메시지나 예약 알림은 보내지 않습니다. 계획 변경 시 이전 판의 요청은 현재 현황에서 제외됩니다.

이 수정은 사용자의 지시에 따라 로컬에만 보관합니다. 별도 요청 전에는 Push/배포하지 않습니다.

## 로컬 추가: 3단계 계획과 경로

홈의 멤버 행에서 메인계획·차선책·차차선책을 작성합니다. 각 계획에 사용할 조건, 행동, 이동/대기 방식과 상세 글 안내를 저장합니다. 이동 계획은 지도 클릭 또는 좌표 입력으로 출발·만남 지점을 정한 뒤 로컬 도로망에서 경로를 만듭니다. 계단 제외 옵션을 제공합니다.

경로는 약 600m 서울숲 예시 지도 안에서만 생성됩니다. 주소 검색·전국 지도 다운로드는 구현하지 않았습니다. 거리 기준 경로이며 실제 재난 시 통행 가능 여부나 안전을 판단하지 않습니다. 글 안내는 도로 이름·방향·거리를 제공하며, 횡단 위치와 건물 출입구 등 현장 표식은 사용자가 보완해야 합니다.

계획 저장 → ‘지도·경로·계획 오프라인 저장’으로 같은 브라우저·주소에 앱, 지도, 경로, 글 안내를 보관합니다. 계획 수정 후에는 다시 저장하세요. 저장 공간 삭제 시 사라집니다. 개인/전체 계획 PDF 버튼은 한글 요약·각 계획의 경로 지도·상세 안내를 실제 PDF 파일로 내려받습니다. 한글은 이미지로 포함되므로 텍스트 검색은 지원하지 않습니다.

검증: `npm test` (도로 연결, 사유지 제외, 계단 회피, 지도 범위, 보행 일방통행, 단절 경로). 오프라인 기능은 빌드 미리보기에서 확인합니다.

## 그룹 대표와 멤버 권한

기존 그룹은 첫 번째 멤버가 대표로 지정됩니다. 대표만 공통 약속·구성원·전체 멤버의 계획을 수정하고 리마인드를 남길 수 있습니다. 대표는 ‘구성원과 상황 수정’에서 대표를 넘길 수 있으며, 지정된 대표는 삭제할 수 없습니다. 일반 멤버는 자신의 3단계 계획만 수정하고 다른 멤버의 계획은 읽기 전용으로 봅니다. PDF와 오프라인 저장은 열람 권한으로 사용할 수 있습니다.

현재는 브라우저 로컬 체험이며 역할 전환을 제공합니다. 실제 로그인 및 서버 권한 검증은 연결되지 않았으므로, 다중 사용자 서비스의 접근 제어를 보장하지 않습니다.

## 그룹과 대시보드 통합

로그인 후 마지막 선택 그룹(없으면 최근 그룹)의 대시보드를 바로 엽니다. 홈 상단에서 그룹 전환과 생성을 제공합니다. 그룹이 없으면 같은 홈에 생성 안내를 표시합니다. 계정이 직접 생성한 그룹은 최대 3개이며 화면과 서버에서 모두 제한합니다. 초대받은 그룹은 생성 수에 포함하지 않고, 대표를 다른 사람에게 넘겨도 원래 생성자의 생성 수는 유지합니다. 기존 그룹에는 생성자 정보를 추가해 보존합니다.

## Vercel Hobby 배포

Vite 화면과 `api/[...path].js` 서버 함수를 함께 배포합니다. Node.js 24를 사용합니다. Turso Starter 무료 저장소를 프로젝트의 Production/Preview 환경에 연결하면 `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`이 서버 환경 변수로 주입됩니다. 키를 VITE_ 변수, 소스, 로그에 포함하지 마세요. 클라우드 환경에서는 로컬 파일 데이터베이스로 대체하지 않습니다.

서버가 테이블을 처음 한 번 초기화합니다. 로컬 기록은 자동 업로드하지 않습니다. 같은 서비스 주소의 요청만 허용하며 배포 환경에서는 Secure/HttpOnly 세션 쿠키를 사용합니다. 쓰기 요청마다 데이터베이스 트랜잭션을 사용해 그룹 생성 한도와 버전 충돌을 검사합니다. 비밀 파일·계정 데이터는 Git에서 제외합니다.
